# 账户权重策略：原子版本、自进化与回滚

## 实现变更摘要

接续已合入的 #1386/#1387；基准 main 为 `2a268b1ee41cb15379aca3f427e9263e2a6d3fdf`。
本轮为 R1 产品能力，不修改治理、依赖、授权、预算或发布门禁。平台端口此前无监听，
继续采用已记录的有界 supervisor fallback；没有启动或部署宿主。

- 将旧草案中“有界步进、版本链、回滚”思想适配到已有反馈文档，替换其独立可变账本
  和吞掉持久化失败的实现；不整包搬运旧 `policy.py`、预算器、告警队列或 watchdog。
- 明确开启后，基于新终态回执的成功率、有限失败类型、完整列表价成本及已知尝试时延，
  每个评估窗口最多增加一个权重，受 Owner 基线、单步比例与总漂移限制。
- 评分、隔离、去重回执、策略版本及审计记录一次原子提交；写入失败时均不前进。
- 回滚创建新版本，要求 expected revision，重新校验当前边界；旧版本越过收紧后的边界、
  版本已被留存策略裁剪或 CAS 冲突时拒绝，文件和历史不变。
- 生产路由从同一次文档读取取得评分及策略，候选证据记录生效版本；关闭自进化立即使用
  当前配置基线，不删除已积累的策略与失败历史。
- 保留本版本未消费的反馈文档分区，避免常规写入擦除未来版本或旧扩展的证据。

## 功能边界

核心目标、唯一任务路由器、TaskStore 真相和 R0–R3 不变。复用已有 SelfEvolutionStore
共享锁与原子替换、终态回执去重、AccountScoreboard、模型路由及 MODEL_SELECTED 证据。
没有新运行时、队列、外部服务、插件管理器或成本计价模型。

允许自动变化的参数仅为 `reliability_weight`、`cost_weight`、`latency_weight`。
不调整额度观测、账户身份、登录态、重试次数、隔离时长、模型权限、预算、运行窗口、
独立审查或发布规则。所有排名调整继续受 #1387 的最大调整量和原硬准入约束。
本轮没有新的公开 HTTP 管理端点；回滚是可信宿主 Python API，不是浏览器侧权限。

## 关键模块

| 模块 | 职责 |
|---|---|
| `multi_account/policy_lifecycle.py` | 无 I/O 的转移计算、当前边界校验、版本历史和回滚 CAS |
| `SelfEvolutionStore.record_account_feedback` | 将策略转移与真实账户反馈、隔离和去重一起提交；可选策略证据异常保留原策略并记录诊断 |
| `SelfEvolutionStore.rollback_account_policy` | 重读后核对 expected revision，再原子提交回滚事件与新状态 |
| `account_routing_state` / dispatch | 一致读取评分与策略，向既有路由快照传入有效权重及版本 |
| `MultiAccountOrchestrator` | 公开只读策略视图和显式回滚方法；保留原 Owner 配置不被自动改写 |
| host 终态反馈 | 继续冻结尝试归属；将有限 timeout 分类保留为独立反馈类型，不扫描任意错误正文 |

## 可配置项

环境入口沿用 `REVERSE_AGENT_MULTI_ACCOUNT_` 加字段名大写；无效、非有限和超界配置
由 Pydantic 拒绝。参数在实例创建时读取，本轮没有热部署或重启进程。

| 字段 | 默认与边界 |
|---|---|
| `enable_policy_evolution` | false；关闭后立即不消费持久化自适应权重 |
| `policy_min_new_attempts` | 30，至少 3；启用时须能装入 `max_recorded_runs` |
| `policy_step_ratio` | 0.1，(0,0.25]，每窗口最多一步 |
| `policy_max_weight_drift_ratio` | 0.25，0–1，相对当前 Owner 权重基线 |
| `policy_target_success_rate` | 0.85，(0,1]，不把额度等待算作质量失败 |
| `policy_audit_limit` | 64，2–256；裁剪历史目标后拒绝对其回滚，revision 不倒退 |
| `policy_observation_max_age_seconds` | 86400，(0,30天]；过期/未来观测不凑新窗口的样本门槛 |
| `max_recorded_runs` | 原默认 500，限制未评估回执窗口；回执去重本身仍有留存边界 |
| `enable_feedback_routing` / `enable_account_scoring` | 沿用 #1387；不开启消费时不改变路由，不开启评分时不推进策略 |
| 主开关、账户、阈值、退避、成本/时长、日志告警 | 沿用既有入口及 Owner window；本轮不扩大或复制控制权 |

固定规则按顺序处理明确账户异常、timeout、排除额度等待后的低成功率、完整成本/时延压力。
相同失败计数采用固定优先级；不是由回执到达顺序随机决定。成本使用全部窗口尝试的列表价
估算除以执行成功数，任一缺失保持 UNKNOWN；“执行成功”不等于独立评审后产品验收。
比较参考由同配置周期首个完整窗口建立，审计保留参考值、参数、摘要、源回执和时间范围。

可信宿主回滚示例（只说明 API，本轮未对真实账本执行）：

```python
view = brain.account_policy_view()
brain.rollback_account_policy(0, expected_revision=view["revision"])
```

`0` 表示当前 Owner 基线；正整数表示仍保留且满足当前边界的历史版本。
关闭开关是无损停用；不使用删除账本或清除历史作为回退。

## 验收结果

开发机 C 盘空间耗尽，首次本地测试因临时目录写入失败中断；该结果未记为通过。
后续将本轮测试基目录设为 F 盘专用的新建路径，保留所有用户数据及失败记录。
当前生命周期专项 17 项通过；整套相关回归 327 passed、6338 deselected，`git diff --check` 通过。
独立 exact-head 评审、完整平台 CI 与最终合入结果见对应 PR。

| 要求 | 本轮隔离证据 |
|---|---|
| 新反馈驱动 | 满足新回执门槛才生成版本；重复与匿名回执不双计或触发自进化 |
| 不混淆状态 | 额度等待不调质量权重；timeout 独立；成本未知不冒充免费 |
| 原子耐久性 | 失败写入不推进评分、版本或回执；失败回滚保留文件、有效参数和历史 |
| 当前限幅 | 收紧配置后，历史越界目标被拒绝；新配置优先且新变化仍受步进与漂移限制 |
| 可审计回滚 | 新 revision 保留 before/after、参数、来源与原因；裁剪/过时 CAS 被拒绝 |
| 实际生产消费路径 | 真实 `_resolve_task_model` 读取版本和权重；回滚后下次选择使用基线且 Owner 配置不变 |
| 连续状态 | 同宿主并发 CAS 只有一个成功；旧半窗口过期后不能凑新样本；未知分区不被擦除 |
| 数值与配置 | 有限极大值不产生非有限文档；环境参数可达；错误配置拒绝 |

## 已知限制与扩展点

1. 默认关闭，未部署、未真实付费试跑、未做 24h/72h/7d 无人值守验收。整体目标保持 active。
2. 单宿主 JSON 事务，不是跨进程共写协议；源回执和历史均有明确留存上限。
3. 自适应权重是在有限规则内响应执行反馈，不证明质量或经济性改善；仍需要同任务、同验收
   标准的受控比较、完整成本归因及真实运行数据。
4. 列表价估算不等于现金或额度账单；生产缺少精确尝试时延时，该项继续 UNKNOWN。
5. 阶段性执行成功不等于独立审查通过；本轮不自动发布策略代码或将未验收结果当作授权。
6. API 提供版本回滚，尚未增加管理界面、外部通知通道或策略灰度实验管理器。
7. 无法解析的可选策略证据会保留，并在对应回执标记 `policy_error`；完整告警投递及恢复
   流程仍须后续闭合。损坏/不可写整个账本不因这一机制变得可用。
