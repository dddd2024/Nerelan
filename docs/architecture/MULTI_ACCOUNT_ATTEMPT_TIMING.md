# 实际执行区间进入账户反馈

## 实现变更摘要

从 main `2a268b1ee41cb15379aca3f427e9263e2a6d3fdf` 分支。已有生产反馈明确拒绝把任务
创建/更新时间差当响应延迟，但尚未提供精确尝试计时，本切片补齐这一来源。
平台未启动或部署；沿用有界 supervisor fallback 开发，测试使用隔离 F 盘临时目录。

主开关开启时，协调器用单调时钟记录真正调用 executor 的区间；在现有 claim 完成、
预算结算和回执事务内保存数字型 `attempt_metrics`。账户反馈只读取匹配 window/epoch
的已完成 reservation；恢复已有结果而未重新执行时，不伪造本次耗时。

## 功能边界

复用原协调器、fenced claim settlement、TaskStore SQLite、反馈和评分链。
不新增事件队列、表、服务、依赖、外部调用或计价模型，不改任务/预算/授权语义。
计时不生成 usage observation，不把零模型检查变成模型调用。

该值是**宿主 executor 尝试耗时**，包含执行与本地校验/回收开销，排除任务排队及先前重试。
它不是上游 TTFT、纯网络响应时间、模型生成速率或真实账单证明。

## 关键模块

| 模块 | 职责 |
|---|---|
| `UnattendedCoordinator` | 仅在实际执行区间采样单调时钟；坏时钟保留 UNKNOWN 并产生固定诊断日志 |
| `ControlStore.complete_task_claim` / `_finalize_task_claim` | 接收可选数字耗时，经原 claim fence 后与结算/回执一起提交 |
| `usage_ledger.task_feedback_metrics` | 只读同一次完成结算中的 schema/basis/state 合法计时；异常计时不遮蔽已知成本 |
| 现有 host / AccountScoreboard | 继续只训练 `attempt_elapsed`；从此可积累实际 latency_samples |

## 可配置项

沿用 `REVERSE_AGENT_MULTI_ACCOUNT_ENABLED`，默认关闭。关闭时协调器不读取尝试时钟、
不扩展 settlement、不改变原反馈行为。没有新计时开关或新的重试、预算、运行时长参数。
评分是否消费、样本门槛、权重及调整上限继续由 #1387 的配置控制。
无实际区间时保持 UNKNOWN；时钟失败不会改任务重试或授权，也不会代入零值。

直接提供无效可选耗时的内部调用，结算保留 `UNKNOWN/invalid_host_timing`；不存原值，
不阻断原本可完成的任务。原回执持久化失败仍按既有规则回滚结算并阻塞窗口。

## 验收结果

新增 19 项测试通过，覆盖真实 coordinator→claim→结算→账户反馈链。
相关协调器和反馈套件的最终数字、独立评审及 exact-head CI 见对应 PR。

| 要求 | 隔离验证 |
|---|---|
| 时延真实口径 | 创建时间设为多年以前，反馈仍只使用单调时钟的 7.25 秒；真实零耗时仍为已知零 |
| 异常连续执行 | NaN、倒退、极值差溢出及布尔时钟不训练时延，任务继续正常结算并输出固定诊断 |
| 原子与 fence | 完成回执失败时，计时与结算一起回滚，原 ACTIVE claim/reservation 保留 |
| 维度隔离 | 损坏/非法计时不把完整可计价 token 变成未知成本；非有限值不进入数字文档 |
| 无效内部输入 | 无效可选耗时只标记 UNKNOWN，原完成流程和预算语义继续 |
| 默认关闭 | 关闭主开关不采样时钟、不增加结算字段、不训练账户 |

## 已知限制与扩展点

1. 未部署、未真实账户试跑、未完成长期无人值守或成本/性能对照。整体目标保持 active。
2. 未捕获到的中断区间无法从任务年龄逆推。恢复已有结果不重新训练一个虚构的新区间。
3. 实际 executor 抛异常而未完成 claim 时，本切片不为它补造完成记录或释放 UNKNOWN。
4. 测量包含本地执行开销，跨账户任务复杂度仍可能不同，不能据此直接宣称 provider 更快。
5. 使用现有结构化日志报告坏时钟；完整运行告警、外部通知投递与质量收益验证仍需后续闭合。
