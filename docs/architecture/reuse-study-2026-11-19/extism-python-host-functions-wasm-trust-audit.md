## 1. Source-backed deep findings and decisions

### A. WASM hosting is useful; **explicit per-Plugin Host Function set is the real permission edge** (**P0 HOST_GATE; P1 BORROW A TINY INTERFACE**)

- [`extism/extism.py` L463–560](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L463-L560) `CompiledPlugin(..., wasi=False, functions=HOST_FN_REGISTRY)` and `Plugin(..., wasi=False, config=None, functions=HOST_FN_REGISTRY)` embed host functions into a compiled/native instance. `Plugin(CompiledPlugin)` inherits functions/WASI and may have different lifetime ownership. The default is **a module-global mutable list**, declared [L19–23](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L19-L23); [`host_fn` L815–911](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L815-L911) appends decorated callbacks. The decorator doc says *thread-local registry*, but code shown is a process/module-level list, not `threading.local()` or `contextvars`. A newly added host function can therefore become exposed to a later plugin constructed without explicit `functions` list; explicit `functions=[]` passes zero host callback pointers. **Do not infer cross-plugin sandbox isolation from WASM alone.**
- [`handle_args` L914–933](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L914-L933) selects Python callback via integer index in `HOST_FN_REGISTRY`; mutable global dispatch is a maintenance and isolation hazard. It does not alone prove exploitation or that an already-created plugin automatically gains newly added native imports, but raises necessity for per-plugin allowlists, scoped lifetime, and namespace checks.
- [`tests/test_extism.py` L163–203](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L163-L203) exercises explicit `functions=[hello_world]` and Wasm-to-Python imports (READ ONLY).
- **Nerelan plan:** host-authorized `PluginCapabilityLease` for exact `pack_id + wasm_sha256 + export_name + callback_set_version + agent_goal/task/attempt/claim_epoch + allowed_workspaces + schema + max_input_bytes + network/credential prohibition`; start with **pure provider-free deterministic functions** `hash, parse_small_json, transform_bounded_bytes`; `functions=[]` unless positive Host grant. Never hand plugin Python `TaskStore`, `ExecutorRouter`, GitHub credential or a bound method with raw host authority. A Pack/Skill manifest is metadata, NOT a self-granting capability.

### B. **P0 security NO-GO: `extism.Pickle` auto-deserializes guest bytes in trusted Python**

- [`extism/extism.py` L26–71](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L26-L71) exposes `Json`, `Pickle`, `Codec` typing annotations for host function ABI. [`_map_arg` L278–314](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L278-L314): when input annotation metadata is `Pickle`, `lambda plugin, slot: pickle.loads(plugin.input_bytes(slot))` executes inside the **trusted Python host process** on guest-provided bytes. Unsafe pickle deserialization can run arbitrary Python code if the plugin can invoke that annotated callback. This is conditional on **Host opting to register a Pickle-consuming function**, not claim that all Extism plugins bypass WASM by default. [`_map_ret` L356–389](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L356-L389) `Pickle` output uses `pickle.dumps`, and [`tests/test_extism.py` L227–244](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L227-L244) tests return-side Pickle; no upstream adversarial malicious-pickle input fixture found in tests read.
- Custom `Codec` likewise runs arbitrary host-chosen decoder logic on untrusted bytes; `Json` is comparatively bounded but parsing alone does not constrain size, depth, business schema, trusted actions or exported provenance.
- **Nerelan fail-closed rule:** deny any `Pickle` on untrusted plugin ingress/egress (including Python helpers parsing plugin results), prohibit unrestricted `Codec`, no `pickle.loads` on child/Agent-provided data. Only explicitly size/depth-limited JSON + schema validation and safe primitive results, then Host reauthorizes side effects.

### C. Host context is a live Python object, not a separate sandbox (**P0 BORROW WARNING; P1 PASS IMMUTABLE DATA ONLY**)

- [`Plugin.call` L598–636](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L598-L636) creates `_ffi.new_handle(host_context)` and passes it to `extism_plugin_call_with_host_context`; [`CurrentPlugin.host_context` L676–695](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L676-L695) calls `_ffi.from_handle()`, returning the original Python object to an approved host callback. [`tests/test_extism.py` L246–279](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L246-L279) **explicitly demonstrates the callback mutating `foo.x = 1000`**. This is intended functionality, not isolation; malicious plugin may indirectly trigger any powers reachable from callbacks and context.
- **Nerelan:** do not put DB session, task store, token store, arbitrary callable, Owner object, GitHub client, model connection, filesystem handle or mutable policy in context; pass opaque Host-checked ID and copy-only reduced dataclass. Host revalidates each action against *current* claim fence/policy/version; byte parsing must precede any callback effects.

### D. Plugin manifest provenance/remote fetch, WASI and native dependency (**P0 SUPPLY_CHAIN TEST_FIRST**)

- [`_wasm` L210–223](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L210-L223) accepts local file paths, JSON serialized manifest, or raw bytes; [`Plugin` doc L515–544](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L515-L544) shows manifest `{"wasm":[{"url":"https://..."}]}` and **optional** `hash`, not an SDK-enforced **required** content hash. [`tests/test_extism.py` L291–303](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L291-L303) uses pinned SHA256 `data/hash` for local test Wasm, but those tests do not prove remote URLs with no hash are prohibited.
- `wasi=True` toggles WASI preview 1 in native core. This SDK layer does not expose a separately authenticated Nerelan Host grant for WASI filesystem/network primitives; actual native allowances and manifest `allowed_paths/allowed_hosts/memory/timeout` are **not deeply audited** because they belong to another project (`extism_sys` / core). **No claim that Wasm or `wasi=False` automatically enforces Nerelan sandbox security**.
- [`pyproject.toml` L1–25](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/pyproject.toml#L1-L25) depends on native `extism-sys>=1.9.1` and `cffi`; version spec is not upper/exact pinned and depends on binary wheel/native library availability. README lists Windows MSVC x86_64 as a **supported target**, not a verified Nerelan Windows installation; a runtime dependency addition is R2, untrusted binary executing is R3 per AGENTS.md.
- **Nerelan:** pre-download module in a separately approved process, enforce `sha256` + provenance + license + policy digest; deny runtime `url` retrieval and arbitrary local module path from untrusted Pack; WASI disabled unless explicit and separately inspected. Tiny provider-free harness only, behind existing CapabilityRegistry & #299.

### E. Timeout, cancellation, use-after-free and retry semantics (**P0 TEST GAP; NOT PROVEN DURABLE**) 

- [`CancelHandle` L455–461](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L455-L461) invokes native `extism_plugin_cancel(pointer)`; [`Plugin.cancel_handle` L580–588](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L580-L588) exposes it. [`tests/test_extism.py` L152–161](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L152-L161) uses a `timeout_ms:1000` manifest and expects a looping plugin to error in ~1 second (**read only, not executed here**).
- **Test gap:** [`tests/test_extism.py` L280–290](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L280-L290) calls `Thread(target=cancel,...).run()`, **not `.start()`**. Python `Thread.run()` executes the function **synchronously in the calling thread**; it sleeps then cancels before the subsequently invoked `plugin.call("infinite_loop")`. This test does **not prove in-flight, concurrent cancellation**, cross-thread callback safety, cleanup on host process death or no lingering native resources.
- [`Plugin.__del__` L638–660](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L638-L660) and [`CompiledPlugin.__del__` L509–513](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L509-L513) free native pointers, with ownership tests [`tests/test_extism.py` L53–120](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/tests/test_extism.py#L53-L120); these are memory/resource cleanup checks, **not** guaranteed external action rollback. [`Plugin.call` L620–637](https://github.com/extism/python-sdk/blob/c4c03cb2162680ad60fea00ca7f1a32a60e690c0/extism/extism.py#L620-L637) returns native output as a buffer if `parse=None`; caller must not treat a borrowed buffer as a durable immutable artifact across plugin destruction/next calls.
- **Nerelan:** watchdogs and memory quota are necessary but plugin cancellation is **not task cancellation or transaction rollback**. Before any Host external callback, write a durable operation intent (TaskStore, per-attempt claim epoch, unique key); on abort/quota/restart, hold UNKNOWN external side effects and avoid automatic duplicate execution. Provider-free cancellation fixture must use `thread.start()` + barrier to ensure call was already running, then cancel with bounded deadline; explicitly test native pointer lifetime and no orphan worker/thread.

## 2. Provider-free fixtures to propose (ALL NOT RUN)

1. **F1 Empty host set:** fresh `Plugin(...functions=[])` has no imports beyond explicitly audited core/WASI; can call only pure exported function, not registered Python file/secret/HTTP callbacks.
2. **F2 Registry contamination:** module A calls `@host_fn` before module B constructs default Plugin; B's import exposure is tested; B explicit allowlist `functions=[]`/specific functions prevents extra imports; compare process-wide vs documentation thread-local assertion.
3. **F3 Registry index mutation:** after making plugin A, reorder/remove/register global registry callbacks; fail closed rather than dispatch to wrong function; separate module/plugin namespaces must not share Owner authority by name/index.
4. **F4 Host-context capability leak:** callback receives mutable object with `TaskStore`/token/client; assert implementation refuses such context; pass opaque Host-checked ID, with forged tenant/Goal/claim denied.
5. **F5 Pickle adversarial input:** plugin-supplied bytes with malicious pickle reduce to forbidden side-effect; Nerelan policy rejects decoder before any call to `pickle.loads`; no arbitrary Codec.
6. **F6 JSON oversized and nesting:** very large nested JSON bytes/invalid schema cannot allocate or execute unbounded callback; size and depth limits before decoding; UNKNOWN result preserved.
7. **F7 Module provenance:** remote URL with missing hash, mutable latest release, local symlink outside approved pack, mismatch SHA must fail admission; digest must match verified bytes actually compiled.
8. **F8 WASI:** `wasi=False` without approved filesystem/env/network; if toggled true, deny until separately reviewed native runtime and policy; no implicit trust of manifest-provided allowed_paths/allowed_hosts.
9. **F9 True in-flight cancel:** run infinite loop on dedicated thread, confirm started via barrier, cancel concurrently, join with bounded timeout; mark timeout/aborted explicitly; no external side-effect replay.
10. **F10 Timeout error:** `timeout_ms` < wall limit, failed guest call returns `ERROR/TIMEOUT` not `COMPLETED`; never count as accepted goal.
11. **F11 Native lifetime:** compiled plugin shared among two instances; release one, other still works; no use-after-free/double-free; treat `parse=None` buffer as borrowed and copy before retaining.
12. **F12 Host callback lost ACK:** callback committed external side effect then guest aborts/timeouts; TaskStore intent/receipt stays `UNKNOWN/PENDING`, Coordinator must reconcile rather than invoke again.
13. **F13 Host callback data exfil:** plugin sends secret in JSON/Codec arg; host strips unapproved content and never logs raw plugin bytes, credentials or borrowed buffer.
14. **F14 Windows support claim:** README lists `Windows (MSVC) x86_64`; provider-free packaging check on actual supported local OS is required before claiming production compatibility; no binary/native dependency installation without separately granted scope.
15. **F15 Workload cost gate:** compare same bounded pure provider-free transformation direct Host vs Extism: success parity, memory/time/CPU/initialization, failure coverage, restart/cleanup; later accepted-goal results must improve *total* cost or safety justification before adoption.

## 3. Decision, execution order, status

**P0** protect Host/Guest trust boundary: don't expose all global registered Python callbacks, don't deserialize untrusted pickle, don't pass powerful mutable Host context, don't treat cancellation as rollback, don't load unsigned/unpinned remote wasm modules. Those are source-backed warnings and proposed Nerelan acceptance tests, NOT proof of a live exploited vulnerability.

**P1** optionally borrow `byte-in/byte-out + explicit host function imports + compiled-module reuse + bounded timeout` for **pure, no-secrets, no-network, provider-free plugins** after #253/#299/#303 gates. **REJECT DIRECT** native dependency adoption into current Host, untrusted `Pickle/Codec`, implicit global registry, turnkey WASI/plugin manager, plugin-side shell/network/auth, second operation ledger or cost path.

**Priority:** retain existing #1696 chaos bed → #1546 DBOS trial → #1575 high-priority fixes; this is R1 docs-only research. Future implementation belongs to existing #253/#303/#299/#790/#447 only after a scoped decision and risk review; no duplicate feature Issue created.

**Actual evidence:** searched Nerelan GitHub and study hub, fetched fixed SHA README/license/SDK source + upstream tests + current Nerelan implementation and Issue owners; did not install Python package, read secrets, invoke Wasm/native runtime, run tests, contact provider/MCP APIs, run CI, run Windows benchmarks, perform independent review, change R2/R3 files or merge. This **does not establish production runtime correctness/security or benchmark economics**.
