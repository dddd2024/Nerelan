## 1. Detailed pinned source / module decision matrix

### A. Virtual MCP target admission before contact — **P1 BORROW_PATTERN; P0 denial gate**

- [`mcp/README.md` L8–18](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/README.md#L8-L18) explicitly splits **target condition** (which upstream servers are selected) and **mcpAuthorization** (which tools/prompts/resources are visible after responses). They are different security checks.
- [`mcp/upstream/mod.rs` L501–569](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/upstream/mod.rs#L501-L569) `target_condition_passes` evaluates expression against per-target authenticated request context and filters the target list during request construction. **No condition = allow inclusion**, and filtering does not mean isolated/authorized tool execution.
- [`mcp/mcp_tests.rs` L231–300](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/mcp_tests.rs#L231-L300) upstream fixture verifies conditionally denied target has `init_count=0`, while unfiltered target is contacted and "all denied" yields empty list. **Tests READ, not run**.
- Nerelan borrow: `PackServerAdmission` *positive* host-signed `server_identity + source/config_digest + owner_scope + allowed transport + capability + expiry` must exist before initializing third-party MCP; rejected server incurs no connection, auth exchange, discovery call or tool schema exposure. For user-supplied repo `mcp.json`, discovery must be inert until [#303](https://github.com/dddd2024/Nerelan/issues/303) approves. **Do not copy condition omitted → include** for untrusted workspaces.

### C. Guardrail ordering and external data egress — **P0 NEGATIVE SECURITY FINDING; NEVER COPY DEFAULT**

- [`mcp/session.rs` L288–321](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/session.rs#L288-L321) **runs `maybe_run_guardrails_call_request` BEFORE `self.relay.policies.validate`**. This supports guardrail-produced CEL metadata, but external guardrails may receive request args prior to final tool RBAC denial. It is not proof of exploit/actual exposure in a Nerelan deployment; it is source-grounded ordering needing a secure trust-domain policy.
- [`mcp/guardrails/mod.rs` L58–110, L166–216](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/guardrails/mod.rs#L58-L216) guardrails are ordered processors, can reject, mutate or call external gRPC service. `Remote.request_headers` defaults to an empty allowed list, whose documented meaning is **forward all incoming headers plus pseudo-headers** unless explicitly disallowed. [`mcp/guardrails/client.rs` L32–66, L320–344](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/guardrails/client.rs#L32-L66) builds remote `McpRequest` containing request params, raw headers, backend names and metadata before invoking policy service. `Authorization`, Cookie, custom tokens may be forwarded unless individually excluded by policy. This is a **source conditional risk, not an observed leak**.
- [`mcp/guardrails/mod.rs` L209–224](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/guardrails/mod.rs#L209-L224) `Remote.failure_mode` defaults to FailClosed, but FailOpen can be configured; [`mcp/guardrails/client.rs` L375–409](https://github.com/agentgateway/agentgateway/blob/ed9b7c49008a211b24107e62ff7ac1890b15dc01/crates/agentgateway/src/mcp/guardrails/client.rs#L375-L409) implements `FailOpen => Pass` on remote RPC/protocol error. Safe config cannot be inferred from presence of guardrail plugin.
- **Nerelan design:** (1) Host authorizes *pre-export* before any remote guardrail/service body or header is sent; (2) explicit per-destination allowlist for headers and params; (3) first-party local redaction/secret scan; (4) last policy decision required again after transformed arguments, with digest of final args & per-tool authority; (5) external guardrail unavailability = deny/hold for protected operations, never bypass. The tool's eventual denial does **not** retroactively undo data already sent to a remote guardrail.

## 2. Concrete provider-free negative fixtures (NOT RUN)

1. **No RBAC rules:** Upstream `McpAuthorizationSet` would allow; Nerelan unapproved repo-provided MCP catalog/server/tool must return `DENY_UNAPPROVED`.
2. **Target condition false:** target has zero initialize, token exchange, auth headers, list calls; unrelated allowed target remains discoverable; all denied = visible empty, with completeness flag.
3. **List vs call:** authenticated actor can `tools/list` tool T but not `tools/call` T, and `tasks/get` but not `tasks/cancel`; each method checks current Host policy and operation receipt.
4. **Guardrail pre-RBAC exfil:** tool denied by RBAC, remote pre-RBAC guardrail is configured: sensitive params/authorization headers MUST NOT leave Host; either coarse pre-export deny or redacted approved egress only.
5. **Empty remote header allowlist:** test `Authorization`, `Cookie`, API tokens, pseudo-headers, non-UTF8 header values. Explicit positive allowlist only; non-allowed source never forwarded to policy service.
6. **Fail-open override:** external guardrail network timeout or protocol violation must fail closed on protected actions, despite upstream `FailOpen` option.
7. **Mutation reauth:** guardrail transforms benign `read` request into destructive `write` with different args; post-transform digest and permission must be re-checked; no execution on stale approval.
8. **Name collision:** two MCP servers both advertise `delete`; unprefixed call fails, never picks first; explicit server ID + schema digest is mandatory.
9. **Stale list/policy drift:** the client saw an allowed tool; server/schema/policy/claim epoch changed before invocation, tool call denied; cache TTL cannot waive current authorization.
10. **Session confusion:** route A session ID passed to route B is rejected even if same name/tool; retry after restart preserves correct scope and verified identity.
11. **Partial discovery:** upstream down/401/403 and `FailOpen` merged catalog must be explicitly marked incomplete vs total available; cost and functionality not inferred from absence, no hidden credential rejection.
12. **Unprefixed list amplification:** N upstreams × 64 pages/bounded per call; apply catalog size/request/timeout/cost budgets, never speculative expansion on tool call without explicit admission.
13. **Remote side effect unknown:** tool execution succeeded upstream then ACK/connection lost; keep external operation `PENDING/UNKNOWN` and do not auto replay on a different server/session.
14. **Economics:** same approved Agent task via direct existing connector vs optional gateway; compare *independently accepted* output and all model/tool/gateway overhead, latency, retries and true receipts. Do not treat a trace/spend estimate as accepted cost or evidence of success.
