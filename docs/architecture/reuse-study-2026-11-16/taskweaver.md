### 使用者体验 / 研发权衡

**用户思维：** 真正值得做的是让用户看到“一条分析结果由哪段代码、哪些输入数据、哪个插件版本、哪个内核会话生成，能否在重启后复现”。比“支持又一个 Agent”更有说明力；当内存态丢失、结果未经保存、计算有网络或外部副作用时，必须明确标记未知/不能自动重放。

**开发者思维：** Host 只接受受信 manifest/版本/运行策略，工具可见性、代码导入、插件初始化和网络调用是**四个不同的权限边界**。将沉重 Jupyter/Docker 依赖仅作为数据分析可选器，不侵入主要编码/发布路径。先修 stall/429/executor failover 的 P0，后做上下文/产物 provenance 的 P1。

## 3. 八个最小可证伪实验（本轮仅设计，未运行）

1. **W1 / Plugin 配置准入**（#253/#303）：恶意 YAML 改 `code:../secret`、重名插件、形状错误/schema 不合法、工作区放替身 .py；需要 Host fail-closed schema/path/plugin signature/Owner approval。上游 `do_validate=False` 为明确负例。
2. **W2 / 未选择插件仍加载**（#253/#790）：10 个 registered plugin，LLM 只需要 1 个，其余有 import-time side effect；不得加载未批准插件，更不能暴露 Host secrets；度量 eager load vs on-demand load 的启动时间/内存/Token/真实安全收益。
3. **W3 / Kernel Secret leak**（#299/#303）：Local inherited `os.environ.copy()` / Docker env/cwd mount / network egress / Docker socket / localhost aliases / Windows Junction；必须没有 Host/Magpie keys、SSH、用户 profile 可读；单纯 AST 验证开关不算 PASS。
4. **W4 / Code AST bypass 与安装副作用**（#299）：直接/间接文件、网络和 subprocess、Python module import side effects、shell/magic/pip lines；AST 可以给出 warning，但 Host sandbox+egress+approval 必须拦截，测试前不运行不受控样本。
5. **W5 / Stateful 分析的恢复**（#1596/#1546）：Kernel 正计算、已生成 DataFrame 未输出、已写文件、已调用外部 Tool、已生成 artifact 但 TaskStore 未记收据；kill/redeploy 后分别按只读效果和 TaskStore epoch 安全 adopt/recompute/PARK；不得重跑非幂等代码。
6. **W6 / 跨任务工作区隔离**（#1508/#303）：不同 Session ID 相同 cwd、symlink/junction、旧进程持续写、Kernel 连接文件复用、另一个 Agent 插件读历史文件；TaskStore workspace lease + process truth 不得混用。
7. **W7 / Plugin output provenance**（#280/#296）：脚本实际 stdout/stderr、数据文件、展示 HTML/图片、代码 digest、输入文件 SHA、插件版本，重启后审计是否能从持久 artifact 复算，不推断 Jupyter 内存值 durable。
8. **W8 / 真实收益评测**（#1527）：同一数据分析 Goal/相同输入/独立验收，现有 ExecutorRouter + Python 脚本 vs 独立 TaskWeaver-like stateful Kernel；比较成功率、tokens、实际 Magpie 费用、重跑次数、人工介入、Win32 适用性、网络/权限和维护成本。未显著优于基线则不增加新 runtime。

**NO-GO**：若 W1/W2 动态加载无 Owner 准入；W3 泄密；W4 误将 AST 当安全；W5 自动重放造成外部副作用；W6 跨任务访问；W7 把内存临时结果当 verified；W8 无 ROI，就不接入。实验需在 fixture/隔离环境，不把恶意样例投到用户机器上。
