### 面向用户的价值

**用户**不必理解嵌套 Agent 的进程树，而是能查看：“为什么这项工作还没完成？哪个负责的 Agent 正等待什么？能不能安全地换模型/执行器？是否会重复改动？”系统应先解决持续运行成功率，再引入“自由成长”的 Agent 树 UI。  
**开发者**可借鉴 3 条技术法则：**（1）监督和执行所有权分离，（2）角色/任务历史不会转移授权，（3）请求、响应、接受、完成与未知状态各有绑定身份/收据**。保留 Python/Windows/TaskStore/ACL/Review 的原有单一权威，跨执行器时只借鉴内核无关数据模型。

## 3. 七个最小可证伪实验（此轮未执行）

1. **H1 / 委派合法性**（#1508）：模型提出二级/三级 Agent 子任务，Host 根据 owner-approved scope、最大深度、并发、worker capability、成本和子目标 DAG 准入；越权子 Agent 请求和同级偷控必须拒绝，合法分支要能并发收敛到独立验收。
2. **H2 / Manager 轮换**（#1508/#1530）：Manager 进程强杀/切换，原 Leader 持有任务并继续；新 Manager 只能指导，不获得其他 Lead 子 Agent 的 stop/retry/merge 权限；旧 Manager epoch 的迟到消息不能改写任务真相。
3. **H3 / 身份 clone/补录**（#303/#789）：复制 session 历史或伪造 owner/role prompt/environment、重复 label、工作区路径换链接；不能产生新授权，不能 adopt 旧人任务；紧急清理仍必须可证明进程/会话真实身份。
4. **H4 / Durable messaging crash matrix**（#1530/#296）：消息创建→目标写 pending marker→接受→Pi history recipient receipt→ACK→finalize 多点 kill，重连不重复/丢失 ack，特别验证 **mailbox rename 未显式 fsync** 与 peer bridge fsync 区别；UNKNOWN 不可标 DONE。
5. **H5 / Agent lost/stalled/quota**（#1530/#1596）：缺真实身份时不可复用；可证明旧 attempt 失败则自动选新 binding；对 stall/429/permission wait 分开处理，避免 Herdsman 全靠 owner 人工下达重启阻塞无人值守。
6. **H6 / Plugin/permission leakage**（#253/#789/#790）：`permission:` 元数据写 deny，模拟可执行 Extension/MCP 在 hook/background process 调用禁用工具；必须由 Nerelan Host 拦截且记录授权收据，工具列表可见性不算执行拒绝。
7. **H7 / 真实经济收益**（#1508/#1527）：同一任务集固定主分支/验收标准，baseline 单 Agent vs 固定 DAG vs 动态嵌套委派；衡量**每个独立验收成功 Goal 的总真实成本**（包括 Manager/Lead/Agent/Reviewer/retries）、成功率、重复外部副作用、用户介入次数、tokens/延时。更复杂的组织树不自动成立为价值。

**NO-GO**：一旦 H1/H2 越过 Owner/TaskStore epoch，H3 经 prompt 伪造获得权限，H4 把消息接受当工作完成，H6 失去 Host 安全边界，禁止实施。H5/H7 不好则推迟此类特性，优先修主执行可靠性。跨平台须先做 Windows provider-free fixture，再决定是否尝试远端 Pi/herdr（默认不装）。
