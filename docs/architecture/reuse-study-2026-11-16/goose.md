## 3. 八组精确实验设计（**本轮未执行**）

1. **G1 / Tool Catalog TOCTOU（#790/#253）**：同一 provider inference 内动态 `tools/list_changed`/插件被替换/同名 Tool schema 变更，旧 lease 只能执行原绑定 ID+schema/显式过期，新 lease 更新；Host 不允许新高危 args 无审批。参照上游 `selection_changes_show_up_in_the_next_lease_only`、`tool_list_changed_during_fetch_prevents_stale_cache` 源码测试。
2. **G2 / Admission vs Owner revoke（#303/#790）**：Tool 已 offered 但 Owner revoke、跨 Repo/task/epoch 重放、切换 GooseMode Auto、误被 annotation 标成 read-only，必须 Host Deny/PARK；**Auto 不能覆盖 Owner NeverAllow**。
3. **G3 / MCP per-call correlation（#790/#1508）**：同 session 两个并发 `tools/call`，MCP 请求 elicitation 未回传 call ID / 回传错 Session ID / 旧响应晚到；歧义必须失败，不把回答给另一 Tool，记录持久待办。
4. **G4 / Scanner and inspector unavailable（#303/#299/#447）**：OSV 500/超时/JSON 无效、未知 stdio 命令、adversary LLM unavailable、inspector `Err`。对已经有 Owner grant 的低风险 read-only 操作可有限继续；未授权 shell/writes/network 必须 fail-closed；检查 FAIL_OPEN 与事件字段不能在 UI 标为 `SCAN_PASSED`。
5. **G5 / Inspector precedence（#790/#303）**：Permission Allow + Security Deny / Egress LOG Allow + Permission Ask / Auto Allow + Security Ask；精确断言优先级 `DENY > REQUIRE_OWNER > ALLOW`，不同 inspector error 不造成 Owner 路由下降。相关上游 `security_inspection_requires_approval_in_auto_mode` 可借鉴测试设计。
6. **G6 / lifecycle and process crash（#790/#1596）**：相同 Extension 并发 enable、MCP 子进程断开、同名进程复用/旧进程消息迟到、configs/credentials 热更新、会话 release 与 held lease 并发；TaskStore claim/lease 独立于 MCP lease，实效 UNKNOWN 时不得无条件重放。
7. **G7 / trusted metadata vs remote MCP（#790/#253）**：恶意 MCP response 自带 `__goose_tool_update_meta`、`goose.mcpApp`、`subagent_session_id` 或 `tools/list` owner metadata；Host 应剥离/重新签注，不接受 MCP 输出作为 Owner approval 或新的 tool allowlist。
8. **G8 / integration ROI and UX（#1527/#280）**：同样一批已独立验收 Goal，当前 CLI-native tools 与安全受限 MCP tool adapter 对照，测启动/热重启稳定性、MCP 失败次数、人工审批、接受率、Magpie provider 真实请求总费用（含 SmartApprove）、跨会话恢复和 Windows 功能性。未显著降低总成本或减少人工介入则不新增 Goose runtime。

**P0**：G2/G4/G5/G7 是强制安全/授权否定门；**P1**：G1/G3/G6 是 MCP 互操作可靠性；**P2**：G8 验证成本/用户收益后再决定整合。当前没有满足 G8 的收益证据，Goose 只是可供研究的源码案例。

## 4. 证据等级、实施归属与最终决议

- **ALREADY_REUSED**：ExecutorRouter、TaskStore lease/claim/epoch/operation receipts/budget reservations、Magpie provider request/credential truth、GitHub Draft+exact-head independent review。
- **BORROW_PATTERN**：带版本和 request identity 的 MCP Tool Lease，Extension Slot 重新使用/预热/进程 start dedup，过滤+命名空间、并发 call/elicitation 关联，分层检查器的负面优先级，防 MCP output 伪造内部元数据，permission file concurrent revoked-write fencing。
- **REJECT COPY**：权限 `Auto` 下对 NeverAllow 的直接 Allow 分支成为 Nerelan Owner rule；把 SmartApprove LLM 判只读当强授权；把 Egress LOG 当网络阻断；把 OSV/Adversary/Checker fail-open 当扫描通过；把进程内 MCP lease 当长期 Goal durable lease；自建 MCP server marketplace；使用不稳定核心 Rust crate 当 Python Host 直接运行时。
- **DIRECT_REUSE**：**NO-GO this round**。Apache-2.0 与公开发布 GDK components 可供未来单独评估，但目前没有跨语言/Windows/现有 Host 权限/真实成本收益证明。符合 Nerelan `AGENTS.md` 的 reuse-first、单一授权权威原则。

**研究实际执行内容**：读取固定上游与 Nerelan main 的源码、上游 AGENTS/许可证/内置测试、对应的现有 Owner Issues，以及 GitHub 历史去重。**没有安装 Goose/Rust、没有运行 `cargo test` 或平台测试、没有启动 MCP Server、没有调用模型/provider、没有执行任何 R3 不可信二进制、没有完成 ROI benchmark、没有修改 Nerelan 运行代码**。后续 docs-only Draft PR 仍需 exact-head CI/独立 Review；作者不能出具自己的 ACCEPT。
