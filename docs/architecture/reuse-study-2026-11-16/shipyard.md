### 开发者与用户视角

- **用户**：同一任务可以看到“哪个 Agent 在哪个机器、在哪一轮、为什么等待、是否丢过恢复证据”。最关键的是不让重启后同一更改重复跑，和用低廉模型/Agent 的结果通过同一验收，而不是再堆一个 Coding Agent UI。
- **开发者**：建议将 Nerelan Executor boundary 的返回契约拆成 `StartRequest(task_id, attempt_id, epoch, idempotency_key, authorization_digest)`、`AcceptanceReceipt(worker_id, session_id, turn_id, event_seq, durable_ref)`、`LivenessSignal(confidence, source)`、`EffectReceipt(status=COMMITTED|UNKNOWN|NOT_APPLIED)`。**这只是验证用模型，不是本轮已批准 API**。考虑其增加的状态、LOC 和迁移负担，优先可选 adapter proof，再决定通用化。
- **插件**：最大价值是可撤销、可定位来源的 UI 贡献与信任收据，不是开放任意插件执行。远程 worker 是可选执行后端，不能替代 Windows local-first。

## 3. 可证伪最小实验与 no-go（此轮未执行）

1. **E1：真实发送后进程崩溃**（#1530/#1546）：模拟发送前、远端接受后、Turn journal 前、Run recStepDone 前四个 cut。重启后匹配 `idem` 必须 adopt 同一 Turn；证据不足时必须 PARK/UNKNOWN 而非重发。检查会否破坏现有取消、超时、计费收据。
2. **E2：不可逆 Shell / webhook**（#1546/#299）：模拟 `git push`、创建 PR、部署命令和 webhook 成功后 crash/timeout；不能从普通 Step replay 推断 exactly-once，提供外部 operation key + readback + fencing；下游不支持 dedup 时禁止透明重试。
3. **E3：跨执行器完整性**（#1527）：OpenCode/Codex/Claude 各模拟 hook 缺 Started、没有 Waiting、进程仍活但模型 stalls/429、终端回显误判；只在有 `turn_id`+结束证据才完成，退化 Screen signals 标注低置信度，计入启动/Prompt/Reviewer 成本。
4. **E4：取消 + 主机分裂/旧执行器回归**（#1530/#1546）：旧 worker 收到 cancel 后继续写；新 worker epoch 才有权发布；断开网络、重连重复事件必须单调收敛。Go 进程自身 Mutex 不能证明跨 box exactly-once。
5. **E5：事件丢失**（#280）：模拟 Event Journal Append→50ms fsync 前断电、Turn ledger 晚写/日志被 prune；必须区分 UI 可补读与安全收据，不允许通过展示 Seq 猜任务已验收。
6. **E6：插件/仓库投毒**（#303/#790/#253）：恶意 `.berth/config.json` / plugin main / MCP tool rerouting、digest 改变、未授权 worktree；即使 plugin 有 UI 能力仍不得接触 Owner secrets、Magpie 账户或执行 shell；只有独立 sandbox/host gate 才执行。
7. **E7：真实经济性**（#1267/#1527/#1531）：同一 Task 3×执行器+多模型，在相同验收、固定 fixture/真实样本下比较平均成本/独立验收成功、等待 token（轮询 vs event-driven）、重复操作率、人工干预次数、失败恢复耗时。若编排/事件持久化开销超过收益，保持现状。

**Go/No-Go**：只要 E1/E2 产生重复外部 effect，E4 允许旧 worker 跨 epoch 发布，E5 把可丢事件误判为验收真相，E6 存在未授权代码执行，均不得引入 Shipyard 作为受信执行核心。性能改善不能覆盖这些硬门槛；且固定源实测未完成，不能声称成本下降。
