### 用户价值、开发成本和产品优先级

**用户视角**：在同一个任务页面，能看清楚：“Agent 需要哪个 Tool、要做什么、为什么必须由我批准、我批准的具体版本是什么、已执行还是仍等待、是否还有其它尚未决议的工具请求；切换模型后是否重复扣费；真实花费是否明确已知”。这比增加一个通用 Agent SDK 更有实际价值。

**开发者视角**：P0 是长跑 stall/429 与 Host 审批、真费用；P1 是 Toolset manifest+typed collision/diff+可恢复 deferred approval；P2 才是按需 Tool 加载和 per-run tool budget 试验。当前 **不批准将整个 Pydantic AI runtime/graph/durable engine 引入 Nerelan**。若有具体 harness×model 优势，作为 #1527 的可选受限试验运行，而非取代现有执行器。

## 3. 八组可证伪实验（**未执行**）

1. **T1：toolset 命名冲突/身份稳定（#253/#790）**。两个 Package 同名 Tool、源端改变 MCP host 或 toolset derived-id、动态 `for_run_step` 增删 Tools；必须拒绝歧义执行并保留已授权调用对应的 exact Tool Definition/Version。
2. **T2：DeferredApproval 假人签名（#303/#789）**。Agent 提交 `DeferredToolResults(approvals={id:True}, answered_by={id:'owner'})`、`approve_all=True`、旧 epoch 同 tool_call_id、重复请求不同 args/Repo、显示卡片后改 Tool args；必须由 Host 收据与 canonical action digest 再验，任何缺授权 DENY，`remaining()` 不遗失未解决请求。
3. **T3：Toolset visibility 与底层执行安全（#253/#790）**。通过 filter/deferred_loading 隐藏 Shell Tool，强行经 Extension/Hook/MCP call 工具、从另一个 Toolset 直接引用；模型不可见≠执行拒绝。只 Host policy 拒绝才为 PASS。
4. **T4：Fallback 分类（#1527/#1596）**。429/rate limit/unavailable/timeout 与 ContentFilterError、安全拒绝、UsageLimitExceeded、模型已部分 streaming/Job suspended，分别 check allowlist；绝不通过换模型绕开合规拒绝、账户禁令或超限；Provider job 不明时 UNKNOWN/PARK，不能双开收费与外部副作用。
5. **T5：累计用量 vs provider calls（#1527）**。同 Goal 上游 SDK fallback 多次错误、provider SDK HTTP retry、server-side continuation、streaming aborted、usage omitted；`UsageLimits.request_limit` 仍可能只有一个历史 response，应通过 Magpie request receipts 把真实总次数/真费用与估价、未知分开展示，不能以 0 记未知。
6. **T6：成本软/硬上限（#1596/#1527）**。超额 token post-response、cost=None、count_tokens_before_request=False；Host 在发起前独立预算 reservation；SDK warnings 非硬限，只有 Owner/TaskStore/Provider Gateway 制度 PASS。
7. **T7：ToolBudgets 跨重启（#1508）**。同一 run 内并发工具调用、失败后重试与 run restart，新 run budget 不应清除 Host 已执行外部副作用/操作授权；区分 run-local anti-loop 与 durable Task-level Budget。
