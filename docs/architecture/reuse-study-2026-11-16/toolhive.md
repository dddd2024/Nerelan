## 1. Source-pinned findings (what works, what does not)

### A. Request-chain admission **BORROW_PATTERN P0**, not a drop-in authorization replacement

[`pkg/runner/middleware.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/middleware.go), [integration test](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/authz_audit_integration_test.go), [method gate test](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/method_gate_integration_test.go).
- `PopulateMiddlewareConfigs` constructs a *specific ordered* middleware chain: body-size limit outermost, optional audit outside auth/authz, authentication, token swap/exchange, optional tools/list + tools/call filters, MCP parser, optional telemetry/rate-limit, mutating/validating webhooks, optional authz, scoped outbound AWS/header secrets, recovery. `Origin` enforcement is added centrally in `runner.Run` instead. The exact ordering matters; it is **not equivalent** to simply installing a tool-filter plugin.
- Source integration tests verify denied `tools/call` returns HTTP 403, backend not invoked, audit log outcome denied; `tools/list` filters and `tools/call` enforce matching policy even when the URL uses `/mcp`, `/sse`, `/x/sse`. `TestTransparentProxyRejectsNonPOSTBodies` ensures methods with illicit JSON bodies do not skip MCP parser. The test is evidence of **upstream** coverage, not Nerelan runtime.
- **Crucial qualifier:** Audit is optional and placed *inside* the body-size limit; requests denied before reaching audit (e.g. size, external origin admission) are not proven logged by that integration test. Design Nerelan's host-level audit intake separately; never claim 'every denied HTTP request is audited.'
- Borrow contract: `(trusted Task/Attempt/Agent identity, MCP server/tool identity/version, operation_id, canonical effective request, active permission snapshot) -> allow/deny + durable append evidence`. Block *before backend effects*. Tool-list filtering alone does not confer security; the host must gate actual calls from SDK, Agent internal MCP, ACP-bridged, and any proxy path.

### B. Default PolicyGate **REJECT_AS_AUTHORITY P0**

[`pkg/runner/policy_gate.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/policy_gate.go), [`pkg/registry/policy_gate.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/registry/policy_gate.go) and respective tests: the registered create/update/delete policy gates default to a `NoopPolicyGate` / `allowAllGate`; they are extensibility hooks, **not** Nerelan Owner-deny-by-default. [`pkg/runner/middleware.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/middleware.go) only constructs Authz middleware when `AuthzConfig != nil`. [`pkg/auth/anonymous.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/auth/anonymous.go) provides explicitly development-oriented anonymous identity (discouraged for production).
- **No-go**: do not use ToolHive's default gate or anonymous mode as Owner delegation, and do not assume an upstream operator permission profile is equivalent to token/credential scope, R3 authorization, or permission to install a binary. Even when a user 'approved a tool' at the client, Nerelan's authoritative policy must still verify it.

### C. **New important negative evidence**: mutation before/after gate sees different request

[`docs/middleware.md` Known limitations](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/docs/middleware.md), [`pkg/webhook/mutating/middleware.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/webhook/mutating/middleware.go), [`pkg/mcp/tool_filter.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/mcp/tool_filter.go):
- ToolHive itself documents **pre-mutation tool-filter/rate-limit mismatch**: the tool-call filter sees original raw request and rate limiter sees pre-mutation request, while a mutating webhook can rename a call and the later authorization uses a republished parsed request. A webhook can therefore change the actual tool into one excluded from the **earlier filtering**; this is documented limitation, **not proof** of bypassing *separately configured* downstream Cedar authorization. Modern MCP headers may remain stale after mutation; ToolHive docs say a conformant Modern backend rejects mismatched header/body, but ToolHive's direct pipeline does not itself enforce that consistency check.
- **P0 design**: after any mutating plugin/hook, re-run *final canonical request* against both tool visibility/capability policy **and** host authorization before side effect, plus compare method/name/body/header and record pre/post digests. Disallow mutation entirely for high-risk calls unless proven safe. Test `allowed public_tool -> webhook rewrites restricted_tool`, tampered tool-id/name/args, Modern header mismatch and stale cached catalog. **No assertion** this yields a confirmed exploit in Nerelan or ToolHive.

### D. Client identity vs upstream credential — **BORROW_PATTERN P0/P1**

[`pkg/transport/middleware/strip_auth.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/transport/middleware/strip_auth.go): removes inbound `Authorization`, `Cookie`, `Proxy-Authorization` before uncredentialed upstream forwarding; client identity must already be checked and only selected downstream credentials should be injected afterward. [`pkg/transport/middleware/token_injection.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/transport/middleware/token_injection.go): OAuth token source failure -> 503 `Retry-After: 10` rather than 401, so clients do not trigger an incorrect new-login flow. [`pkg/secrets/scoped.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/secrets/scoped.go): namespaced internal secrets for registry/workloads/auth/llm and reserved keys; `GetSecret` also **falls back to unscoped legacy secret names during migration**.
- Nerelan already has execution-scoped model-relay credential leases in [`credential_relay.py`](https://github.com/dddd2024/Nerelan/blob/57637b338b896f00f966c60a5c67f3e0e9848c4e/reverse_agent/model_access/credential_relay.py) and separate Connection/Executor/Binding identities in [design](https://github.com/dddd2024/Nerelan/blob/57637b338b896f00f966c60a5c67f3e0e9848c4e/docs/architecture/CONNECTION_EXECUTOR_BINDING_ARCHITECTURE.md). **Do not move provider auth or Magpie subscription pool into ToolHive.** For MCP connectors, derive a separate bounded secret capability by `connector/server + operation + principal + expiry + policy revision`; never forward the incoming Agent/IDE credential to external MCP backend.
- **No-go** for permissive migration fallback: do not adopt bare-key fallback for new Nerelan stores absent an audited legacy migration. 503 is a *connector token-state signal*, not authorization to indefinitely retry or spend.

### E. Lifecycle, version and sandbox — **P1/P2 modular pattern, not full replacement**

[`pkg/runner/config.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/config.go) serializes RunConfig: image/remoteURL/transport, permission profile, allowed origins, tool filtering, authz/audit, secret references, worker generation. [`pkg/workloads/manager.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/workloads/manager.go) has list/run/stop/restart/update/logs and bounded retries; [`pkg/api/discovery_permissions_windows_test.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/api/discovery_permissions_windows_test.go) tests Windows ACL/nonce pre-planted discovery records.
- Borrow *concept*: one hosted MCP-server descriptor with observed image/digest, current protocol capabilities, workload UID/generation, state, known permissions, secret scope, health, revocation and cleanup. Client connect capability vs enabled server vs actual permission vs human-visible tool availability must be separate. Existing Nerelan [`capability_registry.py`](https://github.com/dddd2024/Nerelan/blob/57637b338b896f00f966c60a5c67f3e0e9848c4e/reverse_agent/platform_v1/capability_registry.py) is **metadata only, not package manager/daemon**. #790 owns MCP adapter, #253 Pack manifest, #303 source/config trust, #299 OS isolation, #179 Owner policy. Keep authoritative TaskStore/Goal and existing SSH remote broker.
- **Protocol revision caveat:** [`pkg/runner/runner.go`](https://github.com/stacklok/toolhive/blob/74fbd9b6b04151fc98ecfa640c026ddb8cdd769f/pkg/runner/runner.go) says its readiness probe is pinned to MCP `2025-11-25` initialize and **does not yet support** `2026-07-28` `server/discover` Modern readiness. Nerelan #790 already demands protocol-aware capability negotiation. Must simulate old-only/new-only/dual-stack servers before any ToolHive 'ready' inference.
- A container is not automatically a proven strong sandbox, and ToolHive local Docker/Podman + K8s Operator + Go control-plane can be too heavy for Nerelan Windows local-first. `DEFER` full runtime adoption unless it proves materially better than official MCP SDK + thin governed adapter; keep a conditional isolated-backend evaluation only. Verify project license and transitive dependency/desktop distribution separately before any R2/R3 adoption.

## 3. Minimum falsifiable provider-free tests — all NOT RUN

1. **P0 pre/post mutation escape**: fake MCP proxy with `public_tool` allowed and `private_tool` rejected; webhook rewrites public to private; original `tools/list` filtered. Must deny at final host side-effect gate and leave evidence with original/effective request digests. Check Modern `Mcp-Method`/`Mcp-Name` body mismatch and invalid HTTP methods. Failure to deny => NO-GO.
2. **P0 identity/secret non-leak**: agent/client sends Authorization/Cookie/Proxy-Authorization, backend records request. Backend must never receive inbound credentials; inject only exact scoped upstream token *after* authorized request. Force token refresh failure -> bounded 503 signal, no user forced-login loop; separate success and denial audit when configured.
3. **P0 default-gate denial**: unset AuthzConfig, NoopPolicyGate, anonymous mode, misconfigured policy and SDK bypass path. Nerelan must **refuse activation** absent explicit host policy; no silent degraded gate.
4. **P0 replay and duplicate effect**: backend performs side effect then drops HTTP reply; proxy/agent retries with same call ID and after restart. Never double effect without server dedup/receipt; otherwise park `UNKNOWN` for reconciliation.
5. **P1 version compatibility**: legacy `2025-11-25` initialize, Modern `2026-07-28` server/discover-only and dual-stack; compare readiness against actual negotiated capability; no silent unsupported downgrade.
6. **P1 Windows/local-first lifecycle**: fake server start/stop and crash, injected discovery-file/ACL tamper, group permissions, revoked credential, policy generation drift, container backend unavailable. Clear actionable blocked states and cleanup receipts; compare overhead vs official MCP SDK adapter.
7. **P1 product economics**: fixed task and acceptance; run same permitted tool set across current harnesses with and without shared MCP control-plane, measure tool visibility/prompt tokens, actual gateway token/cache hits, latency, errors, audit completeness, operator attention and *successful-task total cost*. No claim of 85% savings without an independent matched control.

## 4. Final decision and no-go boundary

**`SELECTIVE_BORROW_PATTERN / P0_SECURITY_DESIGN / P2_CONDITIONAL_DIRECT_BACKEND`**. The highest-value unique contribution is **request admission and test discipline** around pre/post mutation, credential stripping, deny-event audit and protocol-version mismatch, not wholesale adoption of another Go MCP platform. **Reject default allow-all, optional authz as implicit safety, old readiness as Modern capability, unscoped legacy secret fallback, ToolHive registry/gateway as duplicate Magpie/TaskStore or a reason to install untrusted code**.

Only source/static review was performed. No security reproduction, no binary install, no provider calls, no production policy changes, no tests, no exact-head CI/independent review or merge claim. GitHub trace shall be research Issue + docs-only R1 Draft PR from fresh main and #1576 dated entry.
