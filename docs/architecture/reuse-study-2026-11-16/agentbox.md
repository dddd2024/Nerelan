## 0. 查重：与现有专题保持独立

`HarnessOffer = { id, capabilities, negotiated, admitted, policyReason, usageEvidence }`；`ApprovalReceipt = { issuer, ownerGrantRef, actionCanonicalDigest, displayedDigest, effectTarget, repo, claimEpoch, expiresAt, signatureOrTrustedHostReceipt }`；`WorktreeClaim = { goalId, taskId, workspaceId, branch, baselineSha, claimEpoch, owner, cleanupEvidence }`；`InboxItem = derived(Goal/Task/Receipt/Review/WorkerState)`。只读矩阵、受信权限和已经存在的 TaskStore/GitHub 事实贯通，不造第二套状态/成本中心。

## 3. 九组能明确判定是否值得做的测试（**全未执行**）

1. **A1 / Adapter 两层准入（#1527/#253）**：Adapter 方法存在但 `available(name)=false`、registered OpenCode 但 not admitted、模型/usage unsupported、已注入 Worker API key；必须拒绝可执行能力、未知费用不能记零、UI 不显示未批准插件。
2. **A2 / 审批签名/变更后执行（#303/#789）**：恶意 worker 自写 `allow:true`、改请求命令、同 request ID 换 input、改卡片显示后再批准、旧 epoch 复用、跨 repo/不同 target replay；Host 必须绑定最初原始动作与用户实际看到的字节并 fail closed。重启私钥失效需显式重新批准。
3. **A3 / 来源伪造（#303）**：向 Agent 可写日志插入 `source:'founder'` 的 false answer/priority/close；不能被当 Owner 授权、不能隐藏真实 Owner 的 Inbox 请求；不能影响执行/发布。
4. **A4 / Worktree owner/race（#1508）**：同 task 多进程同时 acquire、被 kill 后 PID 复用、进程崩在 staging、分支更名、旧 Owner epoch、Windows junction；不能两个 Claim 都成功，不得删除活任务/未合并/dirty branch。
5. **A5 / Local file leak（#303/#253）**：忽略文件里是 `.env`、secret、路径跳转、symlink、大小写路径别名、非忽略文件、任务输出泄露；必须拒绝 secrets 拷贝或仅使用受信短寿命凭证代理，不能因为 `.worktreeinclude` 被列为“allowed”而默认授予 Agent。
6. **A6 / Git facts vs transcript（#280/#1508）**：Agent 使用 shell/heredoc/script 改文件、修改测试绕过失败、同工作区并发改、二进制/大文件；diff provenance 来自 Git actual committed tree、exact HEAD，可标 UNKNOWN/截断，独立 Reviewer 发现 test expectation tampering，不能仅看模型文字。
7. **A7 / Publish crash-gap（#1508/#1546）**：ship script push 成功之后崩在 handled 记录之前，重启重复调用、远端已 merge/PR 已开但本地无 receipt。必须 Github readback + TaskStore durable intent/receipt 且不会重复外部副作用；Agent 不能只写 `ship` label 就自主 merge main。
8. **A8 / Inbox/优先级、自动继续（#357/#280/#1596）**：100 Agent 运行，其中一个需 Owner 批准、一个 Reviewer REJECT、一个 quota wait 可自动恢复、一个 agent 自报最高紧急度、一个被 Owner 手动停止；Inbox 只提示真实 Owner action、按 Owner priority 优先，quota wait 不反复打扰，危机不隐藏，操作可追溯。
9. **A9 / 资源与收益（#1596/#1527）**：同一目标集单工作区 vs 多隔离 worktree，1/3/8 并发 CPU/RAM heavies 及不同 Model×Executor；核查 pressure gate 的吞吐、Stall/429/超时、工作区遗留数、独立验收通过率和**Magpie per-request 全真实成本**。Gate 断开不得越过 Owner 授权。Windows 与远端 GPU 资源需独立分类。

**优先级**：**P0** 永远先守长时间 Goal 完成率、stall/quota failover、授权收据/幂等发布；本轮最高安全增量是 A2/A3/A7。**P1** 快速验证 Harness offer/Inbox worktree 只读模型（A1/A4/A6/A8）；**P2** 资源压力 gate 与独立用户界面细节，先有净收益证据再扩建。
