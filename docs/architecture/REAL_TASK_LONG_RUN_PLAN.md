# 真实任务长跑方案（待 Owner 确认）

目的：让平台在无人值守的情况下连续处理真实开发任务，在真实失败、真实额度变化和一次真实关机下，
验证调度、容错、恢复和反馈优化。探针长跑（`docs/handoffs/2026-11-07-multi-account-long-run-handoff.md`）
只证明账户层稳定，本方案验证的是任务层。

时间均为本机系统时钟（UTC−4）。额度数据取自 2026-11-07 11:08 的真实 Magpie 快照。

## 1. 额度约束：Claude 和 Codex 的周额度不能提前用完

Owner 的唯一预算要求。现状与缺口：

| 账户 | 7 天窗口已用 | 本周已过 | 重置时间 |
|---|---|---|---|
| Claude | 69% | 77.5% | 11-09 00:59 |
| Codex | 74% | 47.9% | 11-11 02:41 |

平台现有保护只防"用到见底"：任务预计用量超过剩余额度减 3% 缓冲时才排除该账户。它不防"太早用完"，
Codex 本周已明显超前，现有规则仍会继续派给它。

**前置改动 A：周额度配速。** 在既有选路器 `model_router.select_model` 的额度过滤里加一条规则：
对 Owner 指定的订阅账户，若 `已用% + 本任务预计用量% > 本周已过时间% + 余量`，排除该候选，
理由记为 `weekly_pace`，写入既有 MODEL_SELECTED 证据，并在账户页显示。

| 配置（`model_routing_overrides.json`，Owner 可改） | 默认 |
|---|---|
| `weekly_pace.accounts` | `["claude", "codex"]` |
| `weekly_pace.slack` | 0.10，即允许比时间进度超前 10 个百分点 |
| `weekly_pace.reserve` | 0.10，任何时候都保留至少 10% 不用 |

按当前数据：Claude 配速线 87%，还有约 18 个百分点可用；Codex 配速线 58%，要到 **11-08 19:15**
才重新可用。这是 R1 改动，走正常的评审与落地流程，合入前长跑不启动。

## 5. 关机恢复

宿主按现有 `dev-up.ps1` 启动，开启 `REVERSE_AGENT_MULTI_ACCOUNT_ENABLED`、`REVERSE_AGENT_MAGPIE` 和反馈路由。
运行期间 Owner 主动关机一次：任务执行到一半时关机，开机登录并打开 Magpie，然后检查任务是否从租约恢复，
有没有重复执行或丢失工作。宿主开机自启需要另装一个启动项，确认后再加。

## 6. 验收标准

| 维度 | 标准 |
|---|---|
| 额度约束 | Claude 和 Codex 全程不越过配速线；所有排除都有 `weekly_pace` 证据 |
| 连续执行 | 无人干预下至少完成 3 个任务到 Draft PR，或给出可解释的阻塞 |
| 容错 | 记录每一次真实失败的类型，以及后续是重试、切换还是降级 |
| 关机恢复 | 关机前未完成的任务恢复后继续；没有同一任务的重复执行，没有丢失已提交的工作 |
| 成本与性能 | 按账户统计 Token、成功率和每个成功任务的耗时；免费和订阅账户分列 |
| 反馈优化 | 记录策略版本变化，以及变化前后的成功率和每成功任务成本；样本不足时如实说明 |
| 可回滚 | 结束后用 CLI 回滚一次策略，确认路由回到基线 |

## 7. 停止条件

任一条件满足即停止派发新任务，已在执行的任务跑完：

- Claude 或 Codex 越过配速线（不应发生，发生即视为改动 A 有缺陷）
- 连续 3 个任务失败
- 窗口 Token 上限耗尽
- 任何任务触及 R2 或 R3 路径（`AGENTS.md`、`docs/agents/**`、`.github/workflows/**`、`landing_review.py`、依赖、密钥）
- Owner 停止窗口
