## 附录：Codex 的调查结论（主机为什么读不到 Codex 用量）

以下是 Codex CLI 只读调查报告的要点（检出 `2d055882`，只读代码，没有运行主机或调用任何服务）：

1. Codex 用量进入选路的途径：本机 CLI 会话日志（`subscription_quota.codex_quota` → `read_codex_history`，
   选路时读，缓存 60 秒）；Magpie 账号观测（`REVERSE_AGENT_MAGPIE=1` 时合并）；任务准入时写入
   `platform_quota_observations`（预测路径只读这张表）；额度等待恢复；公开的 Codex 重置公告（只是触发重读，
   不是用量证据）。
2. 空闲主机上：日志可以读，但读数的时间戳是事件时间，重复读不会变新；多账户监视器只做诊断，不写观测表；
   没有任何后台任务往观测表里写。
3. 主机不会在不跑任务的情况下向 Codex CLI 或其服务查询额度。现有的就绪检查只跑 `exec --help` 和 `login status`。
4. "新鲜" = 观测时间在 600 秒以内（`quota_reservation.py:40–66`）。`model_router.py` 里的 900 秒是重试间隔，
   不是新鲜度。
5. 建议：加一个只读账号额度、不调用模型的后台查询（约 5 分钟一次），并让观测可以独立于任务准入落库；
   备选是用 Magpie 的额度采集。报告当时没有确认 Magpie 会在空闲时刷新；本次会话确认了它会
   （查询时 `readAt` 就是当前时间）。所以备选方案更省事，也就是第 5 节 A1。
